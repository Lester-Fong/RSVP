- **Passed — current verification:** latest applicable execution covers the current delivered slice. It does not mean rerun during this documentation task.
- **Passed previously — needs rerun if affected:** execution evidence exists; rerun when the relevant writer, schema, renderer, configuration or dependency changes.
- **Pending — ready to execute:** coverage/check exists and can be run after its stated safety preflight.
- **Planned — coverage not yet implemented:** proposed automated coverage or an undelivered manual drill. This is **not a skipped test**.
- **Blocked — prerequisite missing:** name the missing environment, implemented path, policy or asset; do not attempt a weaker substitute.
- **Manual acceptance pending:** delivered material awaits explicit owner sign-off; automation cannot supply it.

Gates: **A** feature implementation; **B** milestone automated QA; **C** owner manual acceptance; **D** before pilot/customer sharing; **E** production release readiness. P1 permission, data-integrity and public-media checks at A/B block **activation of the affected feature**. They cannot be deferred to M8 just because release work is scheduled there. P2 is a scoped quality/policy check; an unmet explicitly required gate still blocks that gate. Accepted 1–5C milestones are not reopened by this inventory.

At each milestone closeout, update affected IDs, evidence date/command/environment, and prerequisites. Add newly missing coverage instead of inventing skips.
