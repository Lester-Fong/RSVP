Architecture and deployment

- Additive migration `2026_10_16_075658_create_website_revisions_table` creates `website_revisions` with unique wedding/sequence, version-1 facts/content, nullable photo reference, fingerprint and publication timestamp. Weddings gain a nullable published pointer and monotonic publication counter. Reviewed MySQL DDL, applied to development MySQL without resets, and verified through Boost; no existing wedding was automatically published. A stale development route cache was deliberately cleared. Other environments need the migration, refreshed routes and production build (README.md).
- `WeddingPublication` locks the parent wedding, reloads the draft, validates schema/source/counters/content/media, and inserts the immutable snapshot plus pointer/counter atomically. Wedding facts participate in the fingerprint. Stale/duplicate requests cannot replace a newer publication; model guards reject snapshot mutation. Application publication/public resolution always check same-wedding ownership in addition to the pointer foreign key.
- Public `/w/{slug}` and `/w/{slug}/photo/{photo}` resolve only the active supported snapshot/reference. Draft routes remain owner-only. Public HTML embeds only visible presentation content, excluding auth/accounts, IDs, payment data, counters, schema, paths and fingerprints. Disabled section content is stripped too. Blade/Vue escape strings and Laravel safely encodes embedded JSON.
- Laravel delivers sharing metadata and styled primary invitation HTML, enhanced by the existing Modern Classic Vue component. Styles are shared without changing invitation declarations. Explicit CSS entries support no-JavaScript output. No extra SSR server/package: tradeoff is maintaining the small Blade fallback alongside Vue, covered by parity tests. Production hosting remains separate; localhost URLs cannot be shared over the Internet.
- All revision photo references, including unpublished history, now protect files during draft replacement/removal and pruning. No public disk/symlink/original copies. Historical media is retained indefinitely until an explicit retention/deletion policy is approved; no history/rollback UI.
- Conservative indexing recommendation: `noindex, nofollow, noarchive`, plus private/no-store page/photo responses. Owner should confirm that preference during QA. Existing downloads and third-party preview caches cannot be recalled after unpublishing. Real messaging previews require a reachable deployment.
